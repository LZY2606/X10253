# 电源次序证据室：轨压窗口、依赖约束与启动反例

本目录是**离线案例包**，面向硬件验证团队复核多轨上电/关断序列的完整叙事，
不依赖网络与外部数据库。所有量都带单位与时间基准（`ms-since-enable-assert`）。

## 剧本

| 步骤 | 文件 | 说明 |
|---|---|---|
| 1 | `01-waveform-baseline.json` | 基线波形：三轨采样 + enable/good 信号 + 采样时钟 0.5ms + 测量误差 20mV，原始表示全部保留 |
| 2 | `02-thresholds-v1.json` | 阈值 v1：上升/下降阈值分离（滞回 = rise − fall），最小稳定时间 1ms |
| 3 | `03-dependencies-v1.json` | 依赖 v1：VCC_3V3→VCC_1V8→VDD_CORE，最小间隔 1ms |
| 4 | `04-thresholds-v2-param-revision.json` | **参数修订**：仅 VDD_CORE 下降阈值 0.9V→0.85V → 阈值版本局部过期 |
| 5 | `05-dependencies-v2-cycle.json` | 追加 CORE→3V3 边 → **循环依赖**，系统给出全部最小矛盾边集候选 |
| 6 | `06-waveform-local-source-change.json` | **源数据局部改动**：仅 VDD_CORE 重采样，其余轨逐字节不变 → 只有依赖 CORE 的结果过期 |
| 7 | `07-decisions-script.json` | **互相冲突的人工决定**：接受 vs 否定 → 冲突 → 调整解决 → 撤销，全部写入事件史 |

## 基线中预埋的边界情形

- **滞回**：VCC_3V3 上升阈值 3.0V / 下降阈值 2.7V，状态机在两个阈值间保持原状态。
- **短 glitch**：VCC_3V3 在 t=4.0ms 跌到 2.6V（低于下降阈值）但 0.5ms 内恢复，
  持续时间 < 最小稳定 1ms → 判为 glitch 而非违约。
- **同时到达**：VCC_1V8 与 VDD_CORE 都在 t=2.5ms 开始稳定，|Δ| ≤ 采样容差 →
  无法唯一决定，保留全部合法候选。
- **时钟缺口**：VDD_CORE 在 t=4.0–6.0ms 无采样 → 状态窗口标记为 unknown。
- **关机逆序**：VDD_CORE 在 t=12.5ms 才稳定关断，晚于 VCC_1V8（11.0ms）→
  违反启动顺序的逆序，构成第一个违约证据。
- **循环依赖**：依赖 v2 引入 3V3→1V8→CORE→3V3 环，最小矛盾边集有 3 个合法候选。
- **阈值版本局部过期**：阈值 v2 只改 VDD_CORE，只有 CORE 相关派生结果过期，
  其余结果保持 current；过期结果仍可查看但明确标记，不能冒充当前结果。

## 使用

在应用首页点击「载入案例包并演练」，或手工把各文件内容粘贴到导入框逐条提交。
每一步都会生成事件；回到任意旧事件可看到当时的依赖版本与可见结论。
